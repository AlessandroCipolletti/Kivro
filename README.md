# Kivro

Marketplace for versioned capabilities executed by seller-owned OpenClaw Workers.
The local application uses Next.js, Fastify, PostgreSQL, Redis and S3-compatible
storage. Worker execution runs in a dedicated Docker sandbox, never in the
seller's personal OpenClaw session.

This is a working local implementation, not a completed production release.
Outstanding specification work and external acceptance are listed in
[`docs/implementation-status.md`](docs/implementation-status.md).

## Start Locally

Prerequisites: Node.js 22.13 or newer, pnpm 10.32.1, and a running Docker engine.
OpenClaw 2026.8.2 (0965053) is additionally required for Worker execution.

```sh
cd /Users/cippo/Workspace/Me/Kivro
pnpm install --frozen-lockfile
pnpm dev:setup
pnpm dev
```

Open **http://localhost:3000**. The terminal prints the actual address if the
default port is occupied. The API normally listens on **http://127.0.0.1:4000**.

Setup generates a private `.env`, starts persistent local infrastructure, applies
migrations, creates the development S3 bucket and seeds separate buyer, seller
and administrator accounts. It is repeatable without resetting balances.
Use **Sign in > Buyer login** or **Seller login** in development. Conventional
login uses `buyer@kivro.local` or `seller@kivro.local` and password
`Kivro-demo-password-2026!`. These identities and fake credits are development-only.

The catalog initially contains three offline capabilities. A displayed catalog
entry is not evidence of a running Worker. Purchases remain blocked until the
required device, sandbox, inference, consent and validation checks pass.

## Enable Seller Execution

In a second terminal in the same directory:

```sh
pnpm dev:sandbox
pnpm worker sandbox approve-image
pnpm worker:dev
```

The first command builds the pinned job image, including reviewed Blender and
FFmpeg binaries, and can require several GB of disk space. Image approval runs
real isolation, SSH-backend and OpenClaw configuration checks before recording
the immutable image ID. Development startup can consume the one-time demo
pairing file generated by setup; normal pairing uses the code from Worker health.

Pairing alone does not authorize paid execution. Configure a **dedicated seller
inference credential**, select an actual available model, set explicit provider
pricing and spend limits, run `pnpm worker inference test`, approve the exact
capability manifest, and resume the Worker. Never put provider secrets in a
capability, a chat message, a command argument, or a committed file. The Worker
stores secrets encrypted and does not import personal OpenClaw credentials.

Use `pnpm worker help` for the CLI. Runtime compatibility, approval and provider
configuration are documented in `docs/OPENCLAW_COMPATIBILITY.md`. A missing or
expired prerequisite appears in `pnpm worker doctor` and the Worker-health UI;
there is no insecure fallback. When `pnpm dev` selects a different API port, use
the `API_URL=... pnpm worker:dev` command it prints.

The Marketplace Agent's platform inference is separate from seller inference.
Set `OPENAI_API_KEY` or `ANTHROPIC_API_KEY` in `.env`; the only configured provider
is selected automatically with a pinned, budgeted default model. If both keys
exist, set `PLATFORM_INFERENCE_PROVIDER=openai` or `anthropic`. Custom models and
rates are configurable. See `docs/INFERENCE-PROVIDERS.md`. Without a key, catalog
search remains available; autonomous paid plans are not fabricated.

Local account emails are captured at http://localhost:58025, never sent to the
internet. Production account email requires operator-configured SMTP with verified
TLS. Reset links expire after 30 minutes and invalidate sessions and API keys.

For Stripe test mode, set `PAYMENT_MODE=stripe` and dedicated
`STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET` and, for a separate Connect webhook
destination, `STRIPE_CONNECT_WEBHOOK_SECRET` in `.env`, then restart `pnpm dev`.
Both webhook destinations use `/api/billing/webhook`. Use a Stripe test account
and its test signing secrets, never live keys. Adding a Stripe key alone does not
switch the deterministic local credit adapter. See `docs/BILLING-STATUS.md` for
the provider-backed verification steps and their remaining acceptance limits.

## Verify

```sh
pnpm verify
pnpm test:integration:setup
pnpm test:integration
pnpm test:e2e:web
pnpm test:e2e:web:flows
pnpm test:sandbox
pnpm test:e2e:fixture
pnpm test:e2e:browser-runtime
pnpm test:e2e:faults
pnpm test:e2e:media
pnpm test:e2e:orchestration
pnpm test:fresh-clone
pnpm test:fresh-clone:runtime
pnpm test:e2e:local
pnpm coverage:audit
```

`verify` runs types, lint, unit tests and a production web build.
Integration tests use the real local PostgreSQL and S3 services, including a
separate synthetic resource database. Browser tests need `pnpm dev` running and
Chrome installed (or Playwright Chromium configured in `playwright.config.ts`).
Build verification should run with the development web server stopped because
both Next.js commands write the same build directory.

`test:sandbox` runs actual OpenClaw in the isolated container with a deterministic
**test-only inference fixture**. It checks the bridge and generated files; it is
not a real-provider acceptance run. `test:e2e:local` instead requires a ready,
approved Worker and real inference, creates a paid job using local fake credits,
verifies generated-file download and integrity, and checks exactly-once settlement.
It fails if those prerequisites are absent rather than substituting a mock.

`test:e2e:fixture` checks the complete real API, Worker, Docker/OpenClaw, S3 and
ledger path using an explicitly deterministic local inference fixture and fake
credits. It creates isolated private test identities, performs actual approval
and capability validation, and cleans up its device/session access. It does not
replace real-provider acceptance. See `docs/FULLSTACK-FIXTURE.md` for exact limits.

`test:e2e:browser-runtime` adds the actual buyer-browser upload, consent, purchase
and native result download. `test:e2e:faults` covers critical admission/execution
failures; `test:e2e:media` exercises Blender/file output and
`test:e2e:orchestration` exercises an approved multi-seller DAG producing a PDF.
These use only synthetic identities and deterministic inference/development
payments. Stop the main development API before shared-database runtime fixtures;
do not run browser/storage fixtures concurrently.

The local fake payment adapter is not Stripe acceptance. Stripe test-mode
verification additionally needs the operator's test account, signing secret,
Connect onboarding and reachable webhook forwarding. Do not use live money for
development. `spec/COVERAGE.md` and `docs/LOCAL-VERIFICATION.md` record evidence;
the presence of a test script does not mean its acceptance gate has passed.

`test:fresh-clone` installs a clean temporary source copy from the frozen lockfile,
uses a new database schema and verifies startup through the frontend proxy. It
reuses local data-service containers without replacing them and copies no local
credentials or Worker identity. This is not a second-machine or clean-volume test.
Run it separately from browser tests because the shared development bucket's
browser-origin policy is temporarily updated for the selected test port.

`test:fresh-clone:runtime` additionally executes the actual buyer browser and
Worker job from the clean source copy. It uses an isolated PostgreSQL schema and
an exclusively leased Redis logical database 15, verifies the production queue
processor, then removes only its temporary source/schema/objects/queue. This
command passed locally; its bounded receipt is in
`docs/FRESH-CLONE-RUNTIME-RECEIPT.json`. It remains separate from real-provider and
Stripe staging acceptance.

Private-beta release archives are built with `pnpm worker:package` and
`pnpm build` followed by `pnpm cloud:package`. See `docs/WORKER-RELEASE.md` and
`docs/CLOUD-RELEASE.md`; `pnpm test:cloud-artifacts` checks the extracted API and
web processes in an isolated temporary directory.

## Operations

```sh
pnpm dev:health
pnpm worker health
pnpm worker pause --all
pnpm worker stop --all
pnpm dev:stop
```

Ctrl-C stops the web/API process. `worker pause --all` stops accepting new jobs
without terminating running work; `worker stop --all` requests cancellation of
active work. `dev:stop` stops only the Kivro Compose services and retains data.

`KIVRO_MAX_JOB_PAUSE_MS` sets the cumulative confirmed pause allowance for new
jobs (1,000 to 900,000 ms; default 15 minutes). Each purchase stores its own
immutable allowance. Confirmed pauses do not consume active execution time;
exhausting the allowance releases an undelivered job's reservation. Resuming one
existing job while globally paused requires explicit confirmation and does not
reopen the Worker to new jobs. Security restrictions cannot be overridden.

`pnpm dev:reset --confirm-local-data-loss` removes **Kivro's local service
volumes**. It never resets personal OpenClaw. The local Worker identity remains
separate; after resetting the platform database, re-pair a fresh Worker profile.

Development ports: Postgres 55432, Redis 56379, S3 59000. SeaweedFS supplies the
S3-compatible development store. Application secrets, Worker state, local test
reports and browser screenshots are excluded from Git. Keep `.env` private.

## Structure

- `apps/web`: buyer marketplace, seller operations, contract editor and admin UI.
- `apps/api`: authentication, catalog, dispatch, payment ledger, assets and API.
- `apps/worker`: host-native pairing, consent, durable controls and job execution.
- `packages`: shared contracts/policy, runtime adapter, brokers and orchestration.
- `security/sandbox`: pinned runtime image, narrow tools and isolation probes.
- `spec`: supplied authoritative specification and requirement evidence matrix.
- `docs`: architecture, module status, independent audit and verification evidence.
